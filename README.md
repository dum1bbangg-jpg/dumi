# 두미 · DOOMI

Vanilla HTML/CSS/JS 공개 SPA + 기존 Supabase 어드민/OBS 오버레이.

## 공개 경로

- /#intro: 3분할 사선 이미지 인트로
- /#home: 독립 메인
- /#profile: 별도 프로필 소개
- /#profile/media: 프로필 VOD·클립 탭
- /#schedule, /#song, /#upbo: 기존 기능을 유지하는 공개 뷰
- /#profile/about, /#profile/message: 프로필 소개 탭
- /?embed#schedule: 임베드 진입 예시

각 공개 뷰는 동일 문서에 유지되며 최초 진입 시 데이터 로직을 한 번 초기화한다. 뷰 이동은 화면 가시성·스타일만 전환한다. 검색과 페이지 상태는 유지하고 모달은 닫는다. 재생 중인 VOD는 화면을 떠날 때 중단한다.

옛 /home/, /schedule/, /song/, /upbo/ 주소는 query를 보존하여 해시 화면으로 연결한다. /admin/과 /overlay/는 별도 기능으로 유지한다.

## 에셋 교체

- 인트로: assets/intro/doomi-portrait.png. js/views/intro.js의 INTRO_ART에서 파일과 중심 좌표를 지정한다. 3개 패널 모두 같은 이미지·좌표를 사용한다.
- 메인: assets/main/character.png. 현재는 기존 두미 키비주얼을 사용한다. 투명 배경 세로형 원화로 교체할 수 있다.
- 1.png와 2.png는 로컬 디자인 레퍼런스이며 배포에는 포함하지 않는다.

## 실행

D:/dumi에서 `python -m http.server 8766 --bind 127.0.0.1` 실행 후 http://127.0.0.1:8766 으로 접속한다. 이 정적 서버는 Pages Functions를 실행하지 않으므로 SOOP 프록시 통합 확인은 Cloudflare에서 진행한다. Supabase는 기존 운영 프로젝트에 연결된다.

## 검증

Chromium에서 6개 화면 렌더, 중복 ID와 런타임 오류 검사, 메인 문서 요청 1회 유지, 뒤로 가기, 검색값 보존, 노래 페이지 넘김, 랜덤 모달 정리, UUID 업보 모달·Escape, 일정 목록 7개와 옛 경로·embed 리다이렉트를 확인했다. 운영 DB를 변경하지 않고 데이터가 필요한 상호작용은 요청 목업으로 검증했다.

추가 검증: 940px 임베드에서 모든 공개 뷰를 940×1400으로 재구성. 6주 달+7개 일정, 가로 오버플로 없음, 일정 모달 및 동작 줄이기 설정 확인.

상단 메뉴와 메인 하단의 홈·검색·갤러리·프로필 바로가기를 제공한다. 메인에는 프로필 본문을 병합하지 않는다. 긴 프로필 텍스트는 카드 내부에서 스크롤할 수 있고, 노래책 17곡·업보 16명·미디어 6개는 페이지 넘김으로 모든 데이터를 유지한다.

2026-09-07 수정 검증: 소개/미디어를 포함한 모든 공개 화면의 offsetWidth/offsetHeight/scrollHeight = 940/1400/1400. 6주 달·7개 일정, 40곡·40명·20개 클립 요청 목업으로 확인. 빠른 메뉴의 검색 포커스, 갤러리 탭 진입, 프로필 전환, 미디어 페이지 넘김과 검색 상태 유지 통과.

## 모바일 게시글 임베드

iframe 안에서는 자동으로 화면 너비를 감지해 캔버스 전체를 축소한다. 기존 URL 그대로 사용할 수 있으며 fit 파라미터는 필요 없다. 외부 wrapper는 width:940px;max-width:100%;aspect-ratio:940/1400, iframe은 width/height:100%로 둔다. 명시적으로 ?embed를 넣는 경우에만 기존처럼 메뉴를 숨긴다.

히라 d9a9df7의 iframe 감지·너비 기반 스케일·높이 동기화와 비교해 누락된 자동 감지를 추가했다. 모바일 에뮬레이션/데스크톱에서 360·390·768·940px 각각 6개 뷰를 검사했고, 내부 문서 스크롤이 생기지 않음을 확인했다. 실제 SOOP 앱의 게시글 래퍼 동작은 별도 실기기 확인 대상이다.
